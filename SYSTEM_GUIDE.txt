  Q2. Bakit LSTM? LSTM ba talaga ang system ninyo?   *** ANG PINAKAMAHIRAP ***
--------------------------------------------------------------------------------
  SAGOT (huwag mag-alinlangan, sabihin nang diretso):
  "The system is built around a multivariate LSTM. We tested whether the network
   adds accuracy, and at the current amount of genuinely daily data it does not add
   a significant amount - we tried nine alternative training strategies. So the
   published forecast combines the LSTM hybrid with ARIMA and a weekday-aware Kalman
   filter, weighted by their recent accuracy. That ensemble beats both the naive
   forecast and ARIMA on all eight rice types."

  Ang detalye kung tatanungin pa:
    - Sinukat gamit ang paired McNemar test sa held-out data:
      149 fixes vs 151 breaks, p = 0.95 -> HINDI significant.
    - LSTM mag-isa: skill -1.29% (halos kinokopya lang ang huling presyo).
      LSTM hybrid (LSTM + weekday mean-reversion): +7.80%, 8/8 vs naive, 4/8 vs ARIMA.
      Adaptive ensemble (hybrid + ARIMA + Kalman): +10.06%, 8/8 vs naive AT vs ARIMA.
    - Bakit: ~544 araw pa lang ang tunay na araw-araw na datos (Abril 2025 pataas);
      ang 2015-2024 ay lingguhan. Sa near-random-walk na presyo, ang huling presyo
      ay halos pinakamahusay na hula na. Data-bound ito, hindi model-bound.
    - Nasa system pa rin ang LSTM (component 1 ng ensemble, ~1/3 ng weight).
    - Hindi ito kabiguan. Sinukat namin, at totoo ang inulat namin.

  EBIDENSYA: meta.json -> "lstm_ablation", "hybrid", "ensemble";
             model/experiments/lstm_improve_results.json, transfer_results.json;
             PAPER_CORRECTIONS.md "Adaptive ensemble deployed".

================================================================================
  1. ANO ANG AgriPricePH?
================================================================================

AgriPricePH ay isang rice price prediction system para sa Pilipinas. Kinokolekta
nito ang historical at live data (presyo ng bigas, diesel, USD/PHP, ulan, stock),
iniimbak sa SQLite database, tina-train ang LSTM (o fallback MLP) model, at
nagbibigay ng 3-araw na forecast sa web dashboard para sa LAHAT ng 8 uri
ng bigas. Ang ipinapakitang forecast ay isang adaptive ensemble: ang LSTM hybrid,
ARIMA(1,1,1), at isang weekday Kalman filter, weighted ayon sa accuracy nila.

Mga pangunahing layunin:
  - I-visualize ang presyo ng bigas at related factors (charts)
  - Mag-scrape ng bagong data mula sa DA, fuel site, at exchange API
  - Mag-train ng time-series model batay sa merged daily data
  - Mag-predict ng presyo para sa Day 1, Day 2 at Day 3 (hiwalay na modelo
    kada rice type - 8 modelo lahat)

================================================================================
  6. TRAINING — BUONG COMPUTATION (STEP BY STEP)
================================================================================

Ito ang pinakamahalagang bahagi: eksaktong matematika at proseso mula raw data
hanggang saved model.


--------------------------------------------------------------------------------
  6.1 NORMALIZATION — MinMaxScaler
--------------------------------------------------------------------------------

Bawat feature column (13 columns) ay i-scale sa range [0, 1], fit sa TRAINING rows lang:

  Formula (per column j):
    scaled[i,j] = (value[i,j] - min_j) / (max_j - min_j)

  Sa code:
    scaler = MinMaxScaler()
    scaled = scaler.fit_transform(df[features].values)

  Bakit: Para pantay ang magnitude ng presyo (40-60 PHP), fuel, exchange (50+),
         at stock — mas stable ang neural network training.
         (TANDAAN: hindi feature ang rainfall — tingnan ang Seksyon 4.)


--------------------------------------------------------------------------------
  6.2 SEQUENCE BUILDING — make_sequences()
--------------------------------------------------------------------------------

Gamit ang scaled matrix (N rows × 13 features), bumubuo ng sliding windows:

  Para sa bawat index i mula 0 hanggang N - SEQ_LEN - HORIZON:

    X[i] = scaled[i : i+30]           # shape: (30, 13) — 30 araw × 13 features
    y[i] = scaled[i+30 : i+33, target_idx]   # 3 values — target column lang
    (sa anchored-delta mode, ibinabawas sa train.py ang huling presyo scaled[i+29],
     kaya ang natututunan ng net ay ang PAGBABAGO, hindi ang presyo mismo)

  Halimbawa kung SEQ_LEN=30, HORIZON=3, target_idx=0 (locWellMilled):
    - Input: araw 1-30 ng lahat ng features
    - Output: pagbabago ng locWellMilled sa araw 31, 32 at 33 kumpara sa araw 30

  Bilang ng samples:
    num_sequences = N - SEQ_LEN - HORIZON + 1
    Minimum required: 50 sequences (kung < 50, ERROR at exit)

  Minimum data rows sa DB:
    N >= 30 + 3 + 50 - 1 = 82 araw (praktikal: mas marami para sa train/test split)


--------------------------------------------------------------------------------
  6.3 TRAIN / TEST SPLIT
--------------------------------------------------------------------------------

  REGIME-AWARE CHRONOLOGICAL SPLIT (train.py::_split_indices) — HINDI 80/20,
  at HINDI kailanman shuffled.

    Training   : buong kasaysayan (2015 pataas)
    Validation : kinuha sa daily-observation era (ACTIVE_FROM = 2025-04-01)
    Test       : kasunod ng validation, nasa parehong era

  Aktwal (locWellMilled, mula sa meta.json):
    train_samples = 3713   (2015-01-31 → 2025-03-31)
    val_samples   =  189   (2025-04-01 → 2025-10-06)
    test_samples  =  353   (2025-10-07 → 2026-09-24)
  Porsyento ng "walang pagbabago" na araw: train 81.9% / val 5.3% / test 8.8%

  BAKIT HINDI 70/15/15 (itanong ito ng panel):
  Sa lumang split, 88% ng validation rows ay forward-filled na "walang
  pagbabago sa presyo". Kaya pumipili ng weights ang early stopping base sa
  halos hindi gumagalaw na datos, habang sinusukat ang modelo sa panahong
  gumagalaw ang presyo. Measurement fix ito, HINDI performance fix — pareho
  ang score ng luma at bagong modelo kapag sinukat sa parehong test window.

  Para ma-reproduce ang lumang behaviour: AGRIPRICE_LEGACY_SPLIT=1

  ANTI-LEAKAGE (mahalaga sa panel):
    - MinMaxScaler ay fit sa TRAINING rows lamang
    - Reversion coefficient ay fit sa VALIDATION window lamang
    - Seeded ang runs (AGRIPRICE_SEED, default 42) kaya reproducible


--------------------------------------------------------------------------------
  6.4 MODEL A — TensorFlow LSTM (preferred kung may tensorflow)
--------------------------------------------------------------------------------

Architecture (Sequential):

  Layer 1: LSTM(64, return_sequences=True)  input=(30, 13)
  Layer 2: Dropout(0.2)
  Layer 3: LSTM(32, return_sequences=False)
  Layer 4: Dropout(0.2)
  Layer 5: Dense(16, relu)
  Layer 6: Dense(3)   # HORIZON = 3 outputs

Compile:
  optimizer = "adam"
  loss      = "mse"     # Mean Squared Error
  metrics   = ["mae"]   # Mean Absolute Error (scaled space)

Training loop (bawat epoch, bawat batch):

  LOSS (MSE) — average sa training batch:
    L = (1/n) * Σ (y_true - y_pred)²

  MAE (metric) — average absolute error sa scaled target:
    MAE = (1/n) * Σ |y_true - y_pred|

  Validation: same formulas sa X_test, y_test

  Hyperparameters:
    EPOCHS     = 100 (o AGRIPRICE_EPOCHS env var)
    BATCH_SIZE = 32
    EarlyStopping: patience=8, min_delta=1e-4, monitor=val_loss, restore_best_weights=True
      (TANDAAN: ~7e-4 lang ang delta-target loss, kaya halos hindi umaabot sa min_delta ang
       improvement at maagang humihinto ang training. Sinubukan ang ayos nito (standardised
       targets, min_delta=0) sa experiments/lstm_improve.py V6-V8 - hindi gumanda ang test
       skill, kaya hindi binago ang production. Nakasulat sa PAPER_CORRECTIONS.md.)
    ModelCheckpoint: save best lstm_model.keras kapag bumaba ang val_loss

  Adam optimizer: adaptive learning rate (default Keras settings)


  ANCHORED-DELTA MODE (default, AGRIPRICE_DELTA_MODE=1): ang net ay nagpe-predict ng
  PAGBABAGO mula sa huling presyo; binubuo ulit ang presyo sa inference:
    presyo_h = huling_presyo + LSTM_DELTA_WEIGHT × delta_h        (LSTM_DELTA_WEIGHT = 0.25)


--------------------------------------------------------------------------------
  6.5a LSTM HYBRID — idinadagdag ang weekday mean-reversion term
--------------------------------------------------------------------------------

  Ang araw-araw na pagbabago ng presyo ng DA ay bahagyang bumabalik kinabukasan
  (lag-1 autocorrelation ng daily changes: -0.17 hanggang -0.41).

    hybrid_h = huling_presyo + 0.25 × LSTM_delta_h + phi_h(weekday) × (huling pagbabago)

    phi_h(weekday): OLS coefficient kada forecast day at kada weekday ng huling
                    bulletin, fit sa huling 120 araw bago ang BAWAT forecast,
                    shrink ×0.6, clip sa [-1, 0], gamit lang kung |t| >= 2.
    Bakit weekday: ang Sunday bulletin (mas kaunting palengke) ay ~5× mas maingay
                   at binabaligtad tuwing Lunes.
  Code: model/mean_reversion.py (rolling_phi, WEEKDAY_MODE; AGRIPRICE_REVERSION_WEEKDAY=0 = luma)
  Resulta: skill +7.80% vs naive, 8/8 types; 4/8 vs ARIMA.


--------------------------------------------------------------------------------
  6.5b ADAPTIVE ENSEMBLE — ang PUBLISHED na forecast
--------------------------------------------------------------------------------

  Tatlong forecaster kada rice type at kada forecast day h:
    H = LSTM hybrid (6.4b)
    A = ARIMA(1,1,1), walk-forward
    K = local-level Kalman filter, iba ang noise variance kada weekday

  Weights (Bates & Granger 1969) - galing LAMANG sa nakaraang errors:
    w_m = (1 / MSE_m sa huling 30 realised forecasts) / Σ_k (1 / MSE_k)
    ensemble_h = w_H × H_h + w_A × A_h + w_K × K_h
  Warm-up: 45 origins; kailangan >= 10 errors bago mag-weight (kung hindi, pantay).
  Average weights sa test window: ~1/3 bawat isa (walang iisang modelong nangingibabaw).

  Price range (conformal): half-width = quantile ng |errors| ng ENSEMBLE sa huling
  60 araw, nominal 0.93 → ~90% totoong coverage (nasukat: 91.5%).
  "Steady": kapag |pagbabago| < PHP 0.10 (predict.STEADY_PESO), direction = "steady".

  Code: model/ensemble.py; AGRIPRICE_ENSEMBLE=0 para ibalik ang plain hybrid.
  Resulta: skill +10.06% vs naive (8/8), panalo sa ARIMA 8/8.


--------------------------------------------------------------------------------
  6.6 MODEL B — sklearn MLPRegressor (fallback kung walang TensorFlow)
--------------------------------------------------------------------------------

  Input flatten:
    X_flat = X.reshape(n_samples, 30*5) = (n_samples, 150)

  Architecture:
    hidden_layer_sizes = (128, 64, 32)
    max_iter = EPOCHS (100)
    early_stopping = True, validation_fraction = 0.2

  Training:
    mlp.fit(X_flat_train, y_train)

  Loss (internal): sklearn's squared loss sa scaled y
  Validation loss (printed per epoch):
    val_loss = mean((pred_test - y_test)²)
    mae      = mean(|pred_test - y_test|)


--------------------------------------------------------------------------------
  6.7 METRICS SA REAL PESO (PHP/kg) — Pag-convert mula scaled
--------------------------------------------------------------------------------

Ang y_true at y_pred ay nasa scaled space pa. Para sa interpretable error:

  Para sa MinMaxScaler sa target column (index = target_idx):
    scale_j = scaler.scale_[target_idx]
    min_j   = scaler.min_[target_idx]

  Inverse (mula scaled value p back to peso):
    price_peso = (scaled_p - min_j) / scale_j

  MAE sa Peso (ginagamit sa meta.json):
    mae_peso = mean( | (y_true - y_pred) / scale_j | )

    Equivalent: mean absolute error sa original PHP/kg units

  RMSE sa Peso:
    rmse_peso = sqrt( mean( ((y_true - y_pred) / scale_j)² ) )

  Test Loss (scaled MSE):
    test_loss = mean((y_true - y_pred)²)   # sa scaled space


--------------------------------------------------------------------------------
  6.8 ACCURACY PERCENTAGE (estimated)
--------------------------------------------------------------------------------

  *** DEPRECATED — HUWAG IULAT SA PANEL ANG NUMERONG ITO ***

  avg_price = mean ng actual price sa buong dataset
  accuracy = max(0, min(99.9, 100 - (mae_peso / max(avg_price, 1) * 100)))

  Halimbawa:
    mae_peso = 0.294 PHP/kg, avg_price ~ 44 PHP/kg  ->  ~99.3%

  BAKIT DEPRECATED: ang formula na ito ay nagbibigay ng 98-99% sa KAHIT ANONG
  modelo, at mas mataas pa ang ibinibigay niya sa naive na "bukas = ngayon"
  baseline kaysa sa trained model sa lahat ng 8 rice types. Walang saysay
  bilang panukat. Nananatili lang siya para ma-render pa rin ang mga lumang
  (pre-v4) training runs.

  ANG TAMANG IULAT — HONEST METRICS (meta.json v4, published ensemble):
    hit_rate_pct          — % ng forecasts na nasa loob ng PHP 0.50/1.00/1.50/2.00
                            Aktwal (day 1/2/3): PHP 0.50 → 87.0 / 84.0 / 81.9%
                                                PHP 1.00 → 96.1 / 95.4 / 94.8%
    skill_vs_baseline_pct — lamang kumpara sa naive. Aktwal: +10.06%, 8/8 positive
    beats_arima_count     — ilang type ang panalo sa ARIMA. Aktwal: 8 (hybrid: 4)
    directional_pct       — tama ang direksyon (taas/baba). Aktwal: 57.9-68.9% sa
                            6 na type; impRegular 45.7% at impPremium 50.3% (coin flip)
    directional_n         — ilang totoong galaw ang binilang (para sa binomial test)
    movement_ratio        — gaano gumalaw ang forecast vs totoong galaw.
                            Aktwal: 0.41 (dati 0.07 = kinokopya lang ang kahapon)
    lstm_ablation         — may naiaambag ba ang LSTM? 149 vs 151, p = 0.95, hindi significant
    hybrid / ensemble     — kada type: numero ng LSTM hybrid mag-isa, at ensemble weights

  Ang UI ay nagpapakita na ng hit rate at skill, hindi ng 99.3%. Ang lumang
  numero ay ginagamit lang bilang fallback para sa pre-v4 runs, at naka-label
  na "(legacy)" kapag nangyari iyon.

================================================================================
  7. PREDICTION (INFERENCE) — COMPUTATION
================================================================================

Pagkatapos mag-train, ang predict.py ang tumatakbo sa GET /api/predictions:

Hakbang 1: Load scaler + meta + merged dataframe (same pipeline as training)

Hakbang 2: Transform features
  scaled = scaler.transform(df[features])   # gamit ang FIT ng training, hindi bagong fit

Hakbang 3: Kukunin ang huling window
  window = scaled[-30:].reshape(1, 30, 5)   # huling 30 araw

Hakbang 4: Model forward pass (kada rice type, sariling modelo)
  TensorFlow: delta_scaled = model.predict(window)[0]   # 3 values (day 1-3)
  sklearn:    delta_scaled = mlp.predict(window.flatten())[0]

Hakbang 5: Buuin ang LSTM hybrid (Seksyon 6.5a)
  hybrid_h = huling_presyo + 0.25 × delta_h (sa PHP) + phi_h(weekday) × huling pagbabago

Hakbang 6: Adaptive ensemble (Seksyon 6.5b)
  ensemble_h = w_H × hybrid_h + w_A × ARIMA_h + w_K × Kalman_h
  low/high  = ensemble_h ± conformal half-width (huling 60 araw)
  direction = "steady" kung |pagbabago| < PHP 0.10, kung hindi "up"/"down"

Hakbang 7: Forecast dates
  anchor = HULING ARAW NA MAY PRESYO NG DA (hindi ang petsa ngayon)
  Day h = anchor + h araw   (h = 1, 2, 3)
  (Inayos 2026-09-27: dati petsa ngayon ang anchor, kaya kapag wala pang bulletin
   ngayong araw, "Sep 28" ang label ng forecast na para talaga sa Sep 27.)

Hakbang 8: Change at confidence
  change[i] = price[i] - previous_price
  confidence[i] = hold-out accuracy ng araw na iyon (day-specific)

Hakbang 9: Forward log
  forecast_log.log_payload(): INSERT OR IGNORE kada (origin, rice type, target date) -
  hindi na mapapalitan ang unang forecast. Sinusukat ng GET /api/forecast-check.

Cache: naka-cache ang payload hanggang magbago ang huling araw ng datos o ang
meta.json; pagkatapos ng matagumpay na rice scrape, nire-rebuild ito sa background.

Response JSON: forecast[], current_prices{}, metrics{}, history{labels, values}

  13. FORMULA SUMMARY (QUICK REFERENCE)
================================================================================

  MinMax scale:     x' = (x - min) / (max - min)

  Sequence X:       scaled[t-30 : t]     (30 days × 13 features)
  Sequence y:       delta ng target sa t+1..t+3   (3 days, anchored-delta mode)

  Train/val/test:   regime-aware chronological split (tingnan ang Seksyon 6.3)
                    locWellMilled: 3713 train / 189 val / 353 test

  LSTM loss:        MSE = mean((y - ŷ)²)
  LSTM metric:      MAE = mean(|y - ŷ|)   [scaled]

  MAE peso:         mean(|(y - ŷ) / scale_target|)
  RMSE peso:        sqrt(mean(((y - ŷ) / scale_target)²))

  Accuracy %:       DEPRECATED - huwag iulat (Seksyon 6.8)
  Skill %:          (1 - MAE_model / MAE_naive) × 100
  Hybrid:           last + 0.25·delta + phi_h(weekday)·(last change)
  Ensemble:         Σ_m w_m·forecast_m,  w_m ∝ 1 / MSE_m (huling 30 araw)
  Range:            ensemble ± conformal quantile (huling 60 araw, nominal 0.93)

  Inverse predict:  price = (scaled_pred - min) / scale

  Forecast dates:   Day_k = huling araw na may DA price + k days  (k = 1, 2, 3)
